## 背景與目標

戰術板（`/tactics`）是個人自由擺位的草稿（localStorage、人人可編），不適合承載
**全隊共用、長期使用**的站位體系。本功能新增兩個獨立頁面：

- **防守站位**：先建立基本防守站位，再針對不同情況（對方打 4 號位、2 號位、吊球…）
  設定移動後的站位；切換情況時球員以動畫滑到新位置。
- **接發站位**：兩套接發體系，每套 R1–R6，每個輪轉有「接發站位 → 接發後進攻位置」
  兩個影格，切換時以動畫呈現換位。

**成功的樣子**：教練擺好一次，在場邊用 iPad 點選情況／輪轉，球員就能看到該往哪跑。

主力裝置為 iPad／手機，操作以觸控為主。

## 已確認的決策

| 項目 | 決策 |

| 顯示對象 | 未選賽事陣容 → 顯示位置代號；選了賽事（＋隊別）→ 依主要位置自動預填球員，可逐格改選 |
| 陣容挑選 | 只影響當下顯示，**不寫入 DB** |

| 接發套數 | 2 套固定體系：「舉對＋自由＋1大砲」與「2大砲＋自由」 |

## 1. 頁面與操作

### 路由與權限

| 頁面 | 路由 | 頁面權限 | 編輯權限 |
|---|---|---|---|
| 防守站位 | `/defense` | `defense` | `formations.edit` |
| 接發站位 | `/receive` | `receive` | `formations.edit` |

側欄（`config/nav.ts`）在「戰術板」之後新增兩項，圖示自 lucide 挑選且不與既有項目重複。
不加入 `BOTTOM_TAB_PAGES`。

### 版面

依專案並排規範：`xl:` 以上左右並排（左：影格選擇；右：場地），以下垂直堆疊。

```
┌─ 頂部 ──────────────────────────────────────────────────────┐
│ [陣容：位置代號 / 友誼賽 / 正式比賽 + 賽事 + A/B隊]     [編輯] │
├─ 左：影格選擇 ───────────┬─ 右：場地（我方半場＋球網）───────┤
│ 防守頁：                  │                                   │
│  ◉ 舉球員前排 ○ 舉球員後排 │   ┌──────── 網 ────────┐          │
│  ▸ 基本站位               │   │ ○主攻  ○攔中  ○舉球 │          │
│  ▸ 對方打4號位            │   │   ↘     ↓           │          │
│  ▸ 對方打2號位 …          │   │ ◌副攻 ◌自由 ◌主攻   │          │
│ 接發頁：                  │   └────────────────────┘          │
│  [舉對+自由+1大砲|2大砲+自由]│ 淡色◌＝起始站位，箭頭＝移動方向 │
│  R1 R2 R3 R4 R5 R6        │                                   │
│  ▸ 接發站位 ▸ 進攻位置     │      [◀ 上一步] [下一步 ▶]       │
└──────────────────────────┴───────────────────────────────────┘
```

- 陣容選擇沿用戰術板的 `MatchEventSelector`（含 A/B 隊別），頂部多一個「位置代號」選項
  作為預設。
- 場地為新的輕量元件（只畫我方半場＋球網），球員圖示沿用 `CourtPlayerToken`。
  不重用 `VolleyballCourt`（它與戰術板的名單拖放、畫線工具耦合）；
  場線繪製若能抽成共用片段則抽出，否則獨立繪製。

### 檢視模式（所有人）

- 點選影格 → 球員以約 0.5s transition 滑到新位置。
- 非起始影格：以淡色顯示起始位置並畫箭頭至目前位置
  （防守頁起始＝同組「基本站位」；接發頁起始＝同輪轉「接發站位」）。
- 「上一步／下一步」依左側清單順序逐格切換（接發頁跨輪轉連續前進）。
- 陣容：
  - 「位置代號」→ 圖示顯示代號（舉球、副攻、主攻、攔中、自由）。
  - 選了賽事（＋隊別）→ 依球員主要位置（`primaryPosition`）自動預填各格；
    同位置多人時依背號排序依序填入（主攻1、主攻2…）。人數不足的格子退回顯示代號。
  - 點圖示可改選該格球員；選到已被其他格使用的球員時兩格互換。
  - 防守頁的「前排主攻／後排主攻」各自獨立挑選。

### 編輯模式（具 `formations.edit` 者按「編輯」進入）

- 拖曳球員調整「目前影格」的位置（座標夾在場地＋緩衝區內）。
- 防守頁：新增／改名／刪除／上下移動情況；新增時複製兩組基本站位；
  提供「從基本站位重新套用」（覆寫目前情況目前組別的站位，需確認）。
  「基本站位」本身不可刪除或改名。
- 接發頁：只能拖曳，結構固定（2 套 × 6 輪轉 × 2 影格）。
- 「儲存」整份送出；「取消」放棄本次修改並回到檢視模式。
- 有未儲存修改時離開頁面（路由切換、關閉分頁）提示確認。
- 接發頁「接發站位」影格若違反位置錯誤規則：在相關兩名球員之間畫紅色警示線，
  並於場地下方列出文字說明（例：「4號位（主攻1）須在 5號位（攔中2）之前」）。不阻擋儲存。
  「進攻位置」影格為發球後的站位，不檢查。

### 首次使用

DB 尚無某套資料時，前端載入內建預設站位（標準防守＋預設 5 個情況、兩套標準接發），
以唯讀方式顯示；有權限者按「編輯」後即可修改並儲存，第一次儲存時才寫入 DB。

預設防守情況：對方打4號位、對方打2號位、對方中間快攻、對方吊球、機會球。

## 2. 位置格子、輪轉與資料格式

### 位置格子（DB 存格子代碼，不存球員）

| 頁面 | 格子 | 說明 |
|---|---|---|
| 防守 | `S` 舉球、`OPP` 副攻、`OHF` 前排主攻、`OHB` 後排主攻、`MB` 攔中、`L` 自由 | 固定 6 格 |
| 接發 | `S`、`OPP`、`OH1`、`OH2`、`MB1`、`MB2`、`L` | 7 格；每輪轉 6 格在場上，後排攔中由自由替換 |

### 輪轉定義（5-1，程式常數）

R1 的 1–6 號位：

| 號位 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| R1 | OH2 | MB1 | S | OH1 | MB2 | OPP |

場上示意（自網往端線看）：

```
──────── 網 ────────
 4 OH1    3 S     2 MB1
 5 MB2    6 OPP   1 OH2
```

每得發球權順時針輪轉一格（2→1、1→6、6→5、5→4、4→3、3→2）得 R2…R6：

| 輪轉 | R1 | R2 | R3 | R4 | R5 | R6 |
|---|---|---|---|---|---|---|
| 舉球員號位 | 3 | 2 | 1 | 6 | 5 | 4 |
| 舉球員 | 前排 | 前排 | 後排 | 後排 | 後排 | 前排 |
| 自由替換 | MB2 | MB1 | MB1 | MB1 | MB2 | MB2 |

- 輪轉標籤顯示為「R1（舉球在3號位）」。
- 第一版不提供自訂輪轉順序的介面。

### 位置錯誤規則（僅接發站位影格）

以每位場上球員所屬的號位（自由球員取其替換之攔中的號位）判斷：

- 前排左右：4 號位的 x < 3 號位的 x < 2 號位的 x
- 後排左右：5 號位的 x < 6 號位的 x < 1 號位的 x
- 前後：4 比 5、3 比 6、2 比 1 更靠近球網（y 較小）

x 由左（4/5 號位側）至右（2/1 號位側）遞增；y 由球網往端線遞增。相等視為違規。

### 座標

以「我方半場」為基準正規化：x ∈ [0,1] 對應左右 9m；y ∈ [0,1] 對應球網至端線外緩衝區
（場內 9m ＋ 端線後 2m，供接發站位使用）。幾何常數集中於新模組，與 `lib/court.ts`
的全場座標系互不影響。

### 資料表 `"Formations"`

| 欄位 | 型別 | 說明 |
|---|---|---|
| `Id` | integer identity PK | |
| `Key` | varchar(30) NOT NULL，UNIQUE | `defense`、`receive-opp`（舉對＋自由＋1大砲）、`receive-2oh`（2大砲＋自由） |
| `Layout` | jsonb NOT NULL | 整套內容 |
| `Version` | integer NOT NULL DEFAULT 1 | 每次儲存 +1，樂觀並行控制用 |
| `CreatedAt`／`CreatedByUserId`／`UpdatedAt`／`UpdatedByUserId` | 同既有表 | 由 `SaveChangesAsync` 自動維護；兩個 UserId 加 FK 至 `"Users"` |

`Key` 加 CHECK 限制為上述三值。顯示名稱放前端常數。

### Layout 格式

```jsonc
// defense
{
  "version": 1,
  "bases": {
    "setterFront": { "S": { "x": 0.8, "y": 0.1 }, "OPP": {...}, "OHF": {...}, "OHB": {...}, "MB": {...}, "L": {...} },
    "setterBack":  { ... }
  },
  "situations": [
    { "id": "s1", "name": "對方打4號位",
      "positions": { "setterFront": { ... }, "setterBack": { ... } } }
  ]
}

// receive-opp / receive-2oh
{
  "version": 1,
  "rotations": [
    { "rotation": 1, "receive": { "S": {...}, "OPP": {...}, "OH1": {...}, "OH2": {...}, "MB1": {...}, "L": {...} },
                     "attack":  { ... } }
    // …共 6 筆，rotation 1–6；每筆只含該輪轉在場上的 6 格
  ]
}
```

- 情況清單兩組（舉球員前排／後排）共用；每個情況同時存兩組站位。
- 情況 `id` 由前端產生（短亂數字串），`name` 1–20 字。

### 前端解析器（容錯）

`parseDefenseLayout` / `parseReceiveLayout`：

- 逐格驗證：缺少的格子、非數字或超出 [0,1] 的座標 → 以預設站位對應格補上（座標超出則夾回）。
- 接發每輪轉的格子集合以輪轉定義為準（多餘格子忽略、缺少補預設）。
- `version` 不為 1 或整體格式錯誤 → 整套退回預設，並在頁面顯示「站位資料格式異常，已載入預設」。
- 永不丟出例外。

## 3. API、權限與衝突處理

### API（`FormationsController`，路由 `/api/formations`，`[Authorize]`）

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/api/formations/{key}` | key 對應的頁面權限 | 回傳 `{ key, layout, version, updatedAt, updatedByName }`；尚無資料回 `layout: null, version: 0` |
| PUT | `/api/formations/{key}` | key 對應的頁面權限＋`formations.edit` | 本文 `{ layout, expectedVersion }`；不存在則新增、存在則更新；成功回同 GET 格式 |

- key 白名單：`defense` → 頁面 `defense`；`receive-opp`、`receive-2oh` → 頁面 `receive`。
  非白名單回 404。
- 頁面權限依 key 動態判斷，於 Controller 內檢查 JWT page claim（同 BoardController
  檢查權限 claim 的作法）；無頁面權限回 403。
- `formations.edit` 以 `[RequirePermission(Permissions.FormationsEdit)]` 掛在 PUT。

### 版本號衝突

- 新增：`expectedVersion` 必須為 0；寫入 `Version = 1`。
- 更新：`expectedVersion` 必須等於 DB 現值，寫入 `Version + 1`；不符回 **409**，本文含目前
  `version`、`updatedAt`、`updatedByName`。
- 兩人同時首次新增：第二筆撞 `Key` 唯一索引 → 捕捉後回 409。
- 前端收到 409：顯示「站位已被 ○○ 於 ○○ 更新」，保留本地修改，提供「重新載入（放棄我的修改）」。

### 伺服器端驗證（抽成可單元測試的靜態方法）

- `layout` 必須為 JSON 物件、序列化後 ≤ 64KB、含 `"version": 1` → 否則 400。
- 細部結構由前端解析器負責，伺服器不重複驗證。

### 權限、頁面與 seed

- `Permissions.cs`：新增 `FormationsEdit = "formations.edit"`，加入 `All`。
- `Pages`：新增 `Defense = "defense"`、`Receive = "receive"`，加入 `All`。
- 前端 `authStore.ts` 的 `PAGE`／`PERM` 同步新增；`AdminRoles.tsx` 權限清單新增
  `formations.edit`（標籤「站位編輯」，關聯頁面 `defense`）。
- `SeedRolesAsync`（新建角色）：
  - Coach：頁面加 `defense`、`receive`；權限加 `formations.edit`。
  - Player：頁面加 `defense`、`receive`。
  - Captain／ViceCaptain：頁面同 Player；權限改為獨立的 `[formations.edit]`（不再與 Player 共用）。
  - Admin：既有邏輯自動補齊。
- 增量腳本 `Data/Sql/2026-10-19_AddFormations.sql`（可重複執行）：
  - `CREATE TABLE IF NOT EXISTS "Formations"`、唯一索引、CHECK、FK（`IF NOT EXISTS` 判斷）。
  - `AllowedPages` 含 `"tactics"` 的角色補上 `"defense","receive"`（未含者才補）。
  - `Name` 為 `Coach`、`Captain`、`ViceCaptain` 的角色補上 `"formations.edit"`（未含者才補）。

- 無刪除 API，不涉及 `AuditDelete`。

## 4. 測試

### 前端（vitest）

| 對象 | 驗證 |
|---|---|
| 輪轉計算 | R1–R6 各格號位；舉球員前後排；自由替換哪位攔中 |
| 位置錯誤檢查 | 合法站位無警告；前後排、左右相鄰錯位被抓到；自由依替換攔中號位判斷；相等視為違規 |
| Layout 解析器 | 正常資料原樣保留；缺格、越界、格式錯誤以預設補上且不丟例外 |
| 陣容自動預填 | 依主要位置與背號配對；人數不足退回代號；改選重複球員時互換 |
| 頁面元件 | 無權限看不到「編輯」；切換影格改變球員位置；PUT 回 409 時顯示衝突提示並保留修改 |

### 後端（xUnit）

- key → 頁面權限對照、Layout 驗證（非物件、超過 64KB、缺 version）的單元測試。
- 版本號衝突流程需資料庫，現有測試專案無 DB 整合測試；改於本機 PG17 手動驗證
  （首次新增、正常更新、過期版本 409、無權限 403），步驟列於交付說明。

### 交付前必跑

`npm run lint`、`npm test`、`npm run build`、`dotnet build`、`dotnet test`。

## 不在第一版範圍（YAGNI）

- 多套防守方案（`Key` 結構可擴充，屆時再開放）
- 自訂輪轉順序介面
- 在影格上標示球或對方攻擊手位置
- 自動連續播放（第一版僅上一步／下一步）
- 匯出圖片／PDF
