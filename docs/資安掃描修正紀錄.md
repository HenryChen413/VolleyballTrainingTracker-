## 二、實際修改（vercel.json）

1. **以指定網域覆蓋 `Access-Control-Allow-Origin`**（對應 #2）
   `/(.*)` 與 `/assets/(.*)` 兩區塊均設 `Access-Control-Allow-Origin: https://volleyball-training-tracker.vercel.app`。
   **二次修正紀錄**：第一版誤把 ACAO「移除」，但重掃發現 **Vercel 平台層會在所有回應（HTML + assets）注入 `Access-Control-Allow-Origin: *`**（不在 repo 內，無法用刪除消除）。實測證明 vercel.json 的 ACAO 會覆蓋平台值，故改為明確指定本站網域，將 CORS 鎖回同源（帶任意 Origin 皆回此固定值，跨來源 JS 無法讀取）。兩區塊都設是為避免 Vercel「較精確規則優先」導致 asset 漏設而露出 `*`。

2. **`/(.*)` 加上 `Cache-Control: no-store`**（對應 #8 / #9）
   原因：Vercel 的 `headers.source` 比對「請求路徑」，原本寫的 `/index.html` 規則對 `/`、`/login` 等 SPA 路由比對不到，導致 HTML 套用 Vercel 預設 `public, max-age=0, must-revalidate` 並被 CDN 快取（實測 `X-Vercel-Cache: HIT`、`Age` 數千秒）。改由 catch-all 統一 `no-store`。

3. **刪除失效的 `/index.html` 區塊**
   該規則從未生效（理由同上），由 catch-all 取代。

4. **保留 `/assets/(.*)` 的 `immutable`**
   排在 `/(.*)` 之後，依 Vercel「後者覆蓋」順序，雜湊化靜態資源仍享一年長快取。

## 三、不修改的判定理由

- **#1 CSP style-src 'unsafe-inline'**：Tailwind + shadcn(Radix) 動態注入 inline style 必需；`script-src` 已鎖死 `'self'`，inline style 風險低。Vite 純靜態託管無法簡單導入 nonce，列為已知可接受風險。
- **#3 / #5（HSTS、nosniff）**：線上實測（`curl -I`）兩者皆已存在，為近期 commit 已修，掃描報告過時。重掃即消。
- **#4 / #6（Timestamp、Suspicious Comments）**：
  - 全專案 `src/` 零 `console.*`；Vite 8（Rolldown + Oxc）預設 production minify 已移除全部 `debugger`、剝除一般註解。
  - 殘留註解為 React 等第三方的 `@license` 授權聲明，依 MIT/BSD **須保留**，剝除反而違反授權合規。ZAP 視為「可疑註解」屬誤報。
  - 註：Vite 8 已不支援 `esbuild.drop` / `legalComments`（`build.minify` 僅收 `boolean|"oxc"|"terser"|"esbuild"`），故未調整 `vite.config.ts`。

## 五、正確的 ZAP 掃描方式（避免假象）

**症狀**：用日常 Firefox 掛 ZAP 當代理掃描時，瀏覽器自身的背景流量（Remote Settings、內容簽章、遙測）會被 ZAP 一併攔截，導致報告混入大量「非本站」警示，命中網址為：

- `firefox.settings.services.mozilla.com`
- `content-signature-2.cdn.mozilla.net`

這些是 **Mozilla 伺服器**的問題（跨網域、HSTS、Server 版本洩漏…），與本站無關、也無法修。曾因此把報告從已收斂的結果再次「灌回」9 項，造成誤判。

**正解**：用 ZAP 的 **Automated Scan**，由 ZAP 自己控制瀏覽器並自動限定範圍：

1. ZAP 首頁 → **Automated Scan**
2. URL to attack：`https://volleyball-training-tracker.vercel.app/`（建議用根目錄）
3. Use ajax spider：**with Chrome**（避免 Firefox 背景遙測雜訊）
4. Attack → 完成後看 Alerts 分頁

如此所有警示會限定在 `volleyball-training-tracker.vercel.app`，不再混入 Mozilla 流量。
（手動代理模式的替代做法：在 Sites 樹把本站「Include in Context」、Mozilla 節點 Exclude，並用 Alerts 的「靶心」鈕只看 in-scope。）

## 六、最終可接受基線（2026-05-22，Automated Scan + Chrome）

限定範圍掃描後收斂為 **5 項，全在本站、且全可接受**（1 Low + 4 資訊性），無中/高風險：

| 警示 | 等級 | 命中 | 結論 |
|------|------|------|------|
| CSP: style-src unsafe-inline | Low | /login, /sitemap.xml | Tailwind/Radix 必需，`script-src` 已鎖 `'self'` → 可接受 |
| Information Disclosure - Suspicious Comments | 資訊 | /assets/*.js | 第三方 `@license` 註解，依授權須保留 → 可接受 |
| Modern Web Application | 資訊 | /login, /sitemap.xml | SPA 偵測，純提示 → 無動作 |
| Re-examine Cache-control Directives | 資訊 | /login, /sitemap.xml | 「請複查」非錯誤；HTML 已 `no-store`、asset 正確 `immutable` → 已複查無誤 |
| Retrieved from Cache (Systemic) | 資訊 | 本站多筆 | Vercel CDN 邊緣快取本質，HTML 無敏感資料 → 可接受 |

**結論**：真正的安全問題（CORS/跨網域、HSTS、nosniff、Timestamp、Server 版本洩漏）已全數解決或證實為掃描雜訊；上述 5 項為 SPA + CDN 架構下的固有/資訊性項目，列為已知可接受基線。日後重掃以此為基準對照即可。
