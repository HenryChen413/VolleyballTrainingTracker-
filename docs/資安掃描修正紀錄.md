## 二、實際修改（vercel.json）

1. **以指定網域覆蓋 `Access-Control-Allow-Origin`**（對應 #2）
   `/(.*)` 與 `/assets/(.*)` 兩區塊均設 `Access-Control-Allow-Origin: https://volleyball-training-tracker.vercel.app`。
   **二次修正紀錄**：第一版誤把 ACAO「移除」，但重掃發現 **Vercel 平台層會在所有回應（HTML + assets）注入 `Access-Control-Allow-Origin: *`**（不在 repo 內，無法用刪除消除）。實測證明 vercel.json 的 ACAO 會覆蓋平台值，故改為明確指定本站網域，將 CORS 鎖回同源（帶任意 Origin 皆回此固定值，跨來源 JS 無法讀取）。兩區塊都設是為避免 Vercel「較精確規則優先」導致 asset 漏設而露出 `*`。

2. **`/(.*)` 加上 `Cache-Control: no-store`**（對應 #8 / #9）
   原因：Vercel 的 `headers.source` 比對「請求路徑」，原本寫的 `/index.html` 規則對 `/`、`/login` 等 SPA 路由比對不到，導致 HTML 套用 Vercel 預設 `public, max-age=0, must-revalidate` 並被 CDN 快取（實測 `X-Vercel-Cache: HIT`、`Age` 數千秒）。改由 catch-all 統一 `no-store`。

3. **刪除失效的 `/index.html` 區塊**
   該規則從未生效（理由同上），由 catch-all 取代。

4. **保留 `/assets/(.*)` 的 `immutable`**
   排在 `/(.*)` 之後，依 Vercel「後者覆蓋」順序，雜湊化靜態資源仍享一年長快取。

## 三、不修改的判定理由

- **#1 CSP style-src 'unsafe-inline'**：Tailwind + shadcn(Radix) 動態注入 inline style 必需；`script-src` 已鎖死 `'self'`，inline style 風險低。Vite 純靜態託管無法簡單導入 nonce，列為已知可接受風險。
- **#3 / #5（HSTS、nosniff）**：線上實測（`curl -I`）兩者皆已存在，為近期 commit 已修，掃描報告過時。重掃即消。
- **#4 / #6（Timestamp、Suspicious Comments）**：
  - 全專案 `src/` 零 `console.*`；Vite 8（Rolldown + Oxc）預設 production minify 已移除全部 `debugger`、剝除一般註解。
  - 殘留註解為 React 等第三方的 `@license` 授權聲明，依 MIT/BSD **須保留**，剝除反而違反授權合規。ZAP 視為「可疑註解」屬誤報。
  - 註：Vite 8 已不支援 `esbuild.drop` / `legalComments`（`build.minify` 僅收 `boolean|"oxc"|"terser"|"esbuild"`），故未調整 `vite.config.ts`。
